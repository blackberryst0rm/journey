00

First: are you even in the right layer?

All three are LangChain products and stack on each other. Here's the map.

LangChain

High level · easiest

Prebuilt building blocks. Wire a model + a connector and go. Least control.

Use for: a simple agent with a prebuilt connector to one thing.
◀ YOU ARE HERE

LangGraph

Low level · the runtime

You control every step: state, nodes, routing, memory, human-in-the-loop. It's a runtime, not an app framework.

Use for: your CRUD MVP — “create 10 teams w/ schedules + escalation policies.”

Deep Agents

Harness · Batteries included

Sits on top of LangGraph. Built-in planning (ToDo tool), subagents in parallel, persistent memory, context window management.

Use for: the future full auto-provisioner (big JSON, parallel ops, progress tracking).

Learning LangGraph now is the foundation — Deep Agents is built on it, so nothing is wasted when you scale up.

02

The literal build process — same 5 steps every time

This is the “Thinking in LangGraph” sequence. Do them in order. Green boxes = your PagerDuty version.

1

Map the workflow as discrete steps

List the distinct things that happen. Each one becomes a node. Sketch how they connect.

PD: read request → decide what to create → call CRUD tool → confirm/report
▼
2

Identify what each step needs

Tag each node by type: LLM (reason/decide), Data (fetch), Action (do something external), User input (need a human).

PD: “decide” = LLM step · “create team” = Action step (your FastAPI tool)
▼
3

Design your state

The shared notebook. Rule: store raw data, not formatted text. Ask “does this need to persist across steps?” → yes = it goes in state.

PD state: the request, what's been created so far, tool results, errors
▼
4

Build your nodes

Each node is a plain Python function: takes state → returns updates to state. Decide error handling per node here.

PD: one node calls your CRUD tool; another decides if all 10 teams are done
▼
5

Wire it together & compile

Connect nodes with edges, then .compile(). Add a checkpointer if you want memory or human-in-the-loop.

PD: compile, run, watch it loop until all teams exist

05

Your MVP, specifically

// don't over-engineer this one

“Create 10 teams with schedules + escalation policies” is a tool-calling loop, not a complex branching workflow. The shortcut (create_react_agent) gives you the whole ReAct loop with Claude already — you likely don't need to hand-build a StateGraph yet.

  • Wrap each PagerDuty CRUD call as a @tool with a sharp docstring.
  • Hand the tools to create_react_agent("anthropic:claude-...", tools=[...]).
  • Add a checkpointer only when you want it to remember progress or pause for approval.
  • Reach for the full StateGraph (steps 1–5 above) when you need parallel creation, branching, or custom retry/recovery — i.e. heading toward the Deep Agents provisioner.
# the whole MVP shape — fill in your real CRUD tools
from langgraph.prebuilt import create_react_agent
from langchain_core.tools import tool

@tool
def create_team(name: str) -> dict:
    """Create a PagerDuty team. Use when a new team is requested."""
    return pd_api.post("/teams", {"name": name})

# ...create_schedule, create_escalation_policy, etc.

agent = create_react_agent(
    "anthropic:claude-sonnet-4-5",
    tools=[create_team, create_schedule, create_escalation_policy],
    prompt="You provision PagerDuty. Confirm before deleting anything.",
)
agent.invoke({"messages": [{"role":"user","content":"Create 10 on-call teams..."}]})
